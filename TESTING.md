# Testing and Results

This file documents how the results in the paper were produced and checked, so that readers can
verify them independently.

## How the results were produced

All numbers, tables and figures come from executing the code in this repository with the settings in
`config.yaml` (seeds 11, 23 and 47). No result was typed in by hand or generated by an AI tool. The
`results/` folder holds the exact outputs of the run described below.

| File in `results/` | Content | Paper item |
|---|---|---|
| `summary.csv` | Utility, six threat scores, EPGI per configuration (mean of 3 seeds) | Table II |
| `raw_results.json` | Per-seed values for every configuration, scrub lists, scrub history | Table II, F6 |
| `agencale_decisions.json` | Agent escalation trace, gate decision per configuration, example evidence log | Table II (Gate), F7 |
| `timing.csv` | Encoding, scrubbing and attack-suite time per configuration | Table III |
| `scaling.json` | Scrubbing-loop time and memory at 2,500 to 20,000 calibration notes | Section VI-A |
| `epgi_weights.csv`, `epgi_dirichlet.json` | EPGI under alternative threat weightings | Section IV-E |
| `scrub_recovery.json` | Precision and recall of the learned scrub list | F6 |
| `fig_*.png` | Figs. 1 to 3 | Figs. 1 to 3 |
| `run_log.txt` | Console log of the run | |
| `environment.txt` | Hardware and library versions | Section V-D |

## Reproduction check

The results were first produced in the author's working environment. The packaged repository was then
copied to a fresh folder and run end to end with `./run_all.sh results`. The outputs were compared:

| Check | Result |
|---|---|
| Largest absolute difference in any metric of `summary.csv` | 5.7 x 10^-7 (floating-point noise) |
| Scrub lists and advantage history, all seeds | Identical |
| Agent decision in every seed | CALE-S released; identical |
| Run time | About 20 minutes |

Timing values (`timing.csv`, `scaling.json`) depend on hardware and will differ slightly between runs.

Environment: 2-core Intel Xeon @ 2.80 GHz, 8 GB RAM, Python 3.13.16, numpy 2.5.3, pandas 3.0.5,
scipy 1.18.1, scikit-learn 1.9.1, ff3 1.0.3.

## Known limitations of the tests

* The population is synthetic and its contextual cues are planted, so results show the mechanism, not
  performance on real notes.
* Text adversaries are trained TF-IDF models, not large language models.
* Three seeds of one generator measure run-to-run stability, not robustness across datasets.

See the Limitations section of the paper for the full list.

## Correction made during revision

In the submitted version, CALE's internal adversary was trained on part of the same released notes that
the external attackers were tested on. The revised code trains it only on 5,000 calibration notes of
records outside the release. After this fix CALE's mean text advantage for exact ZIP rose from 0.003 to
0.012 (0.027 in the worst seed) and CALE-S's EPGI from 0.058 to 0.059. Conclusions are unchanged.
