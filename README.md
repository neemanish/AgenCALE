# AgenCALE: Agentic Context-Aware Leakage-guided Encoding

Code and synthetic benchmark for the paper *"AgenCALE: An Agentic Privacy-Preserving Framework for
Contextual Leakage Detection, Adversarial Evaluation, and Auditable Data Release"* (M. Gupta).

All data is synthetic and generated by the code. No personal data is used or distributed.

## What is here

| File | Purpose |
|---|---|
| `config.yaml` | Every parameter used in the paper: seeds, population size, cue rates, k, epsilon, delta, m, calibration size, gate thresholds |
| `privenc_experiment.py` | Synthetic population generator, 12 encoding configurations, attack suite A1-A4, utility models, per-stage timing |
| `agencale.py` | The five agents (threat, encoding, adversary, utility, governance), the coordinator loop, and the privacy gate with SHA-256 evidence logs |
| `scaling.py` | Cost of the leakage-guided scrubbing loop at 2,500 to 20,000 calibration notes |
| `analyze.py` | Summary metrics, EPGI, EPGI under alternative threat weightings, timing table, Figs. 2-3 |
| `fig_agents.py` | Fig. 1 (agent architecture) |
| `run_all.sh` | One command that regenerates every table and figure |
| `requirements.txt` | Pinned library versions |

## Reproduce the paper

```bash
pip install -r requirements.txt
./run_all.sh results
```

Runtime is about 20 minutes on a 2-core Intel Xeon @ 2.80 GHz with 8 GB RAM (Python 3.13).

| Output in `results/` | Paper item |
|---|---|
| `summary.csv` | Table II (utility, threats, EPGI) |
| `agencale_decisions.json` | Table II gate column, finding F7, example evidence logs |
| `timing.csv`, `scaling.json` | Table III and Section VI-A (computational cost) |
| `epgi_weights.csv`, `epgi_dirichlet.json` | EPGI sensitivity to threat weights (Section IV-E) |
| `scrub_recovery.json` | Finding F6 (scrub list precision and recall) |
| `fig_agents.png`, `fig_frontier.png`, `fig_heatmap.png` | Figs. 1-3 |

Seeds are 11, 23 and 47 (`config.yaml`). Every random draw is seeded, so results are deterministic for a
given library version; timing values depend on hardware.

## Results and transparency

* `results/` contains the exact outputs reported in the paper, produced by `./run_all.sh results`.
* `TESTING.md` explains how results were produced, how they were verified, the key numbers, and a
  correction made during peer review.
* `AI_DISCLOSURE.md` states how AI tools were used in this research.

## Notes on the design

* The internal adversary used for scrubbing (A_int) learns only from 5,000 calibration notes of
  non-member records. The external text adversaries are trained on a seeded 20% sample (2,000 notes) of
  the encoded released notes, with labels from the generator's ground truth, and tested on the other 8,000.
* Agents are deterministic software components, not LLMs.
* FF3-1 is used only as a baseline. The NIST SP 800-38G Rev. 1 second public draft no longer specifies
  FF3-1; do not use it in production.
